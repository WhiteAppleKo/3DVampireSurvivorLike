# **일일 작업 일지 (2026-02-06) - 2**

## **1. 리팩토링 개요**
*   **목표**: 증강(Augment) 및 선택지 시스템을 **DLV(Data-Logic-Visual) 아키텍처**로 완전히 전환하여 스탯 계산의 무결성을 확보하고 시스템 간 결합도를 낮춤.
*   **핵심 성과**: 
    1. **중앙 집중형 스탯 계산**: `RuntimeData`가 증강 수치를 누적하고 스스로 최종 스탯을 계산하는 `RecalculateStats` 로직 도입.
    2. **증강 적용 자동화**: 전역 증강 획득 시 리스트에 저장하고, 새로 추가되는 무기에 자동으로 기존 증강이 적용되는 파이프라인 구축.
    3. **레거시 호환성 유지**: 기존 시스템의 `FinalStats`와 UI 구조를 유지하면서도 내부 로직은 DLV 모델을 따르도록 브릿지 로직 구현.

## **2. 신규 및 수정 스크립트 목록**

### **[데이터 및 모델 레이어]**
*   `RuntimeDataPlayer.cs` (수정): 최대 체력 및 이동 속도 증강 누적 필드 추가, `RecalculateStats()`를 통한 동적 스탯 갱신.
*   `RuntimeDataWeapon.cs` (수정): 공격력, 공격 속도, 사거리 증강 수정자(Modifier) 로직 및 딜레이 최소값 보정 추가.

### **[로직 및 시스템 레이어]**
*   `Weapon.cs` (수정): `ApplyPureAugment()` 추가. `PureData`를 해석하여 모델의 스탯을 변경하고 레거시 스탯과 동기화.
*   `AutoAttack.cs` (수정): `m_PureGlobalAugments` 리스트 관리 및 `AddWeapon` 시 기존 증강 자동 적용 로직 구현.
*   `ChoiceApplySystem.cs` (수정): `ApplyAbility()` 내 DLV 데이터 분기 처리 완성 (체력, 이속, 무기 강화 등).

### **[비주얼 및 UI 레이어]**
*   `BindImageText.cs` (수정): `PureDataStatAbility`, `PureDataWeaponAbility` 저장 및 전달 로직 최적화.

## **3. 수정 전/후 상세 비교 표**

| 항목 | 수정 전 (Legacy) | 수정 후 (DLV Architecture) |
| :--- | :--- | :--- |
| **스탯 수정 방식** | 외부에서 `FinalStats`의 변수를 직접 수정 (데이터 오염 위험). | **Model 내부에서 증강 수치 누적** 후 `RecalculateStats`로 최종값 산출. |
| **무기 증강 동기화** | 새로운 무기 획득 시 기존에 얻은 증강을 수동으로 적용해야 함. | `AutoAttack`이 전역 증강 리스트를 관리하여 **신규 무기에 자동 적용**. |
| **선택지 처리** | `ChoiceApplySystem`에서 복잡한 조건문으로 스탯 직접 조작. | 선택된 `PureData`를 모델에 전달하면 **모델이 스스로 상태 갱신**. |
| **데이터 무결성** | 스탯이 여러 번 중복 계산되거나 누락될 가능성이 높음. | 모든 계산이 `PureData`를 기점으로 수행되어 **항상 일관된 결과 보장**. |

## **4. 리팩토링 코드 사용 가이드 (How-to-Use)**

### **① 신규 증강 타입 추가 절차**
1.  **Model 수정**: `RuntimeDataPlayer` 또는 `RuntimeDataWeapon`에 누적할 필드와 `RecalculateStats` 계산식 추가.
2.  **Logic 연결**: `Weapon.ApplyPureAugment` 또는 `ChoiceApplySystem.ApplyAbility`에서 해당 타입을 처리하도록 `switch`문에 추가.
3.  **Data 생성**: `PureDataStatAbility` 등 SO 에셋을 생성하여 수치 설정.

### **② 데이터 변화 감지**
*   UI 또는 다른 시스템에서 스탯 변화를 알고 싶다면, 모델의 `OnStatsChanged` 또는 `OnHpChanged` 이벤트를 구독하세요.

## **5. 주요 수정 및 해결 내역**
1.  **네임스페이스 참조 오류**: `_02.Scripts.AutoAttack` 내에서 `Features.Augment`를 찾지 못하는 문제를 `using` 구문 명시를 통해 해결.
2.  **API 불일치 에러**: `RuntimeDataWeapon`의 `UpdateStats`가 세분화된 modifier 메서드로 교체됨에 따라, `Weapon.cs`의 레거시 호출부를 최신 API로 갱신.
3.  **증강 누락 방지**: `AutoAttack.AddWeapon` 시점에 이미 획득한 증강이 새 무기에 적용되지 않던 구조적 결함 해결.
