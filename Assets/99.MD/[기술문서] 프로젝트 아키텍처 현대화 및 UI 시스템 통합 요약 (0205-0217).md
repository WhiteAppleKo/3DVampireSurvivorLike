# **프로젝트 아키텍처 현대화 및 UI 시스템 통합 요약 (2026-02-05 ~ 02-17)**

## **1. 개요**
지난 2주간 본 프로젝트는 분산된 레거시 시스템을 정리하고, **데이터 주도 설계(Data-Driven Design)** 및 **통합 UI 프레임워크**를 구축하는 대규모 아키텍처 개편을 진행했습니다. 이 과정을 통해 프로젝트의 확장성과 코드 가독성이 획기적으로 향상되었습니다.

---

## **2. 주요 아키텍처 변화**

### **[1] 레거시 코드 정리 및 도메인 분리**
*   **상태**: 프로젝트 전반에 산재해 있던 구형 스크립트들이 최신 시스템과 충돌하는 문제 발생.
*   **조치**: `Assets/02.Scripts/Legacy/` 폴더 내의 모든 구형 파일을 `.txt` 확장자로 변경하여 컴파일 대상에서 일괄 제외.
*   **구조화**: `Assets/02.Scripts/Features/` 폴더를 중심으로 기능별(Player, Monster, Weapon, Augment 등) 도메인 분리 및 네임스페이스 재정립.

### **[2] 통합 하이브리드 UI 프레임워크 구축**
*   **기존 문제**: 타이틀 버튼과 인게임 선택창의 스크롤/애니메이션 로직이 중복 구현되어 유지보수가 어려움.
*   **해결책**:
    *   **`BaseHybridScrollUIView`**: 추상 클래스 기반으로 모든 스크롤 인터랙션(마우스 휠, 드래그, 키보드)과 하이브리드 UX(가변 스케일링) 로직을 단일화.
    *   **`ButtonUIView`**: 데이터 바인딩과 시각적 피드백을 통합 관리하는 공용 컴포넌트 구현.
*   **성과**: 타이틀과 인게임 UI가 완벽하게 동일한 고퀄리티 인터랙션을 공유하며, 신규 UI 추가 비용을 최소화함.

### **[3] 데이터 주도 로직 실행 (Command Pattern)**
*   **전략**: 로직 시스템(LogicSystem)의 거대한 `switch-case` 분기문을 제거하고, 기능 실행 권한을 데이터(ScriptableObject)에게 위임.
*   **구현**: `IBindableUIContent.Apply()` 인터페이스 도입.
*   **결과**: 
    *   `PureDataButton` 자식 클래스들이 버튼 클릭 시의 개별 동작을 스스로 정의.
    *   `PureDataAugment` 자식 클래스들이 증강 획득 시의 플레이어 강화 로직을 스스로 수행.
    *   새로운 능력이나 버튼 추가 시 기존 시스템 코드 수정 없이 신규 클래스 생성만으로 기능 확장 가능.
