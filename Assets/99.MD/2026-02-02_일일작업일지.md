# 일일 작업 일지 - 2026년 2월 2일

## 오늘 진행한 작업
1.  **Projectile 회전 문제 해결** (`Projectile.cs`)
    *   **문제점:** 기존 원형 투사체 대신 방향성이 있는 모델을 사용할 때, `LookAt`을 사용하면 모델의 축 문제로 인해 엉뚱한 방향을 바라보는 현상 발생.
    *   **해결책:** `rotationOffset` 벡터 변수를 추가하여 인스펙터에서 모델별 회전 보정값을 설정할 수 있도록 기능 개선. `SetTarget` 메서드에서 타겟 방향을 계산한 후 오프셋을 적용하는 방식으로 수정 제안.

2.  **몬스터 스폰 가중치 시스템 구현** (`RepeatSpawner.cs`)
    *   **문제점:** 여러 종류의 몬스터가 동일한 확률로 등장하여 다양성이 부족함.
    *   **해결책:** `GetEnemy` 메서드에 '가중치 기반 확률 뽑기(Weighted Random Selection)' 알고리즘 도입.
        *   전체 가중치 합(`m_TotalEnemySpawnWeight`) 내에서 랜덤 값을 뽑아, 누적 가중치와 비교하여 스폰할 몬스터 종류를 결정.
        *   `foreach` 문법 오류(중괄호 누락) 수정 및 예외 처리(타겟 못 찾았을 때 대비) 추가.

3.  **몬스터 몸통박치기 구현 방안 논의**
    *   **논의:** 몬스터 충돌 데미지 구현 시 `Weapon` 상속 여부 고민.
    *   **결론:** 단순 충돌 데미지는 `Weapon` 상속이 과하므로, 별도의 가벼운 컴포넌트(`MonsterBodyAttack`)를 만들어 `BattleManager`와 연동하는 방식을 추천.

4.  **광역 무기(AoEWeapon) 타겟팅 로직 개선** (`AoEWeapon.cs`)
    *   **문제점:** `AttackLogic`이 `EnemyController`만 감지하도록 작성되어 몬스터가 사용할 경우 플레이어를 공격하지 못함.
    *   **해결책:** `EnemyController` 대신 부모 클래스인 `Controller`를 감지하도록 변경하고, 자신(`m_Controller`)은 공격 대상에서 제외하는 로직 추가 제안.

## 새롭게 배운 점 (또는 리마인드)
*   **유니티 좌표계와 모델링 툴의 차이:** 모델링 툴마다 전방(Forward) 축이 달라(Max는 Y-up, Blender는 Z-up 등 설정에 따라 다름) 유니티로 가져왔을 때 `LookAt`이 의도대로 동작하지 않을 수 있음. 이를 해결하기 위해 Import Settings를 수정하거나 코드 상에서 오프셋을 주는 방법이 있음을 재확인.
*   **가중치 확률 알고리즘:** 단순 랜덤(`Range(0, Count)`)보다 가중치 기반(`Range(0, TotalWeight)`) 방식이 게임 밸런싱에 훨씬 유연함을 확인함.

## 직면했던 문제점
*   **구문 오류:** `RepeatSpawner.cs`의 초기 코드에서 `foreach`문의 닫는 중괄호가 누락되어 컴파일 에러가 발생할 수 있는 상태였음. (수정 제안 완료)
*   **타겟팅 유연성 부족:** 무기 스크립트들이 `EnemyController`에 강하게 결합되어 있어, 몬스터가 무기를 사용하거나 아군을 치유하는 등의 확장성이 부족했음. (상속 구조 활용 제안)
